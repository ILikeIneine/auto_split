# Auto Split

点击网页链接，使用 Chrome **原生 Split View** 在当前窗口右侧打开；原页面留在左侧。新建分屏默认等宽（1:1）。

## 安装

1. 使用 **桌面版 Chrome 155 或更高版本**。
2. 在 Chrome 地址栏打开 `chrome://extensions`，开启「开发者模式」。
3. 点击「加载已解压的扩展程序」，选择 **`G:\auto_split\extension`** 文件夹（不是项目根目录）。
4. 刷新已有网页，再点击普通链接即可。也可将 Auto Split 固定在工具栏，点击图标暂停或恢复。

源码无需 npm install，无需构建，也不需要 API Key。压缩包仅包含可加载的 `extension` 文件夹；使用压缩包时请先解压。

## 行为

- 第一次点击：当前页在左，目标链接在右，创建两个真正的 Chrome 标签页组成的原生分屏。
- 再从左侧点击：复用并导航右侧，保留左侧页面、滚动位置和状态。
- 打开和更新右侧时不主动切换焦点；从左侧点击后，键盘焦点仍留在左侧，需要操作右侧时再手动点击右侧。
- 从右侧点击：在右侧继续浏览，左侧仍保留。
- 已经手动创建的分屏：按标签顺序识别右侧，直接复用。
- 关闭右侧或手动取消分屏后：下次点击重新创建。后台休眠或重启后无需保存配对关系。
- 暂停开关：全局生效，不会取消已经存在的分屏。
- Ctrl / Command / Shift / Alt + 点击、中键、下载、页内锚点、非 HTTP(S) 链接、命名框架导航保持原有行为。
- 普通 `<a target="_blank">` 同样在右侧打开。具有真实链接的前端路由会优先交给分屏处理。
- 支持注入到 HTTP(S) iframe；其中的普通链接也会打开到标签页右侧。

## 比例与适用范围

Chrome 的 `tabs.create({ splitWithTabId })` 默认把新标签放在右边；新建布局默认比例为 0.5。**扩展 API 没有分屏宽度或方向设置参数**，因此本插件不能锁定比例、重置手动拖动后的比例，或将已有的上下分屏改为左右分屏。复用已有分屏时保留它原来的布局。

插件处理网页内真实的 HTTP(S) `<a href>` 链接。地址栏导航、书签、表单提交、纯 JavaScript 按钮、`window.open()`、封闭 Shadow DOM 内的链接及浏览器内部页面不在处理范围内。Chrome 网上应用店等受保护页面不允许注入脚本。安装、重新加载扩展后，需要刷新已经打开的网页。脚本初始化完成前的极早点击仍按原方式处理。

如果创建失败或通信中断，会保留原页面并显示提示，提供「在新标签页打开链接」供手动继续，不再自动替换左侧页面。只有点击已被拦截、但用户随即暂停插件时，才恢复在原页面访问目标的行为。

## 闪白优化（1.0.1）

新建分屏使用 `active: false`，复用右侧时只更新 URL，不再调用 `active: true`。这减少由插件触发的焦点切换，并避免失败回退导航左侧。它是对可能触发闪白的操作的优化，尚未在用户出现问题的网站上验证效果。

创建或关闭原生分屏仍会改变左侧视口宽度，可能引起浏览器重绘或网站自身响应式处理。扩展没有在 Chrome 原生关闭按钮生效之前拦截关闭、冻结左侧绘制的接口，无法承诺彻底消除这类闪白。继续查看多个链接时，保留分屏并让插件复用右侧，可以减少反复创建和关闭布局。

本地验收页有「闪白诊断」：打开和关闭右侧时，观察左侧的文档标识、加载次数、resize 和 focus/blur 计数。文档标识不变说明该文档没有重新加载；如果仍闪白，需进一步排查重绘或网站局部渲染。

权限仅包含 `storage` 和 HTTP(S) 内容脚本的网页访问范围，用于本地保存开关和拦截链接。无远程服务、统计或上传；不申请 debugger 权限，不改网站响应头。

## 验证

```powershell
cd G:\auto_split
npm test
npm run demo
```

随后在装有扩展的 Chrome 中打开 <http://127.0.0.1:8765>。验收步骤：

1. 点击「文章一」：确认原页面保留左侧、文章一出现在右侧，内容区域约各占一半（分隔线和浏览器边框除外）。
2. 从左侧点击「文章二」：右侧路径变为 `/article-two`，标签总数不再增加。
3. 从右侧继续点链接：左侧路径不变，右侧继续导航。
4. 测试下载、锚点、修饰键、前端路由，以及固定标签和标签组中的链接。
5. 暂停后普通点击恢复网页自身行为；恢复后无需刷新。安装或重新加载扩展仍需刷新网页。
6. 关闭右侧，再从左侧点链接：可以重新创建分屏。

自动化测试使用 Node 内置测试运行器和 Chrome API 模拟，覆盖首次分屏、复用、并发点击、后台重启、失败回退和链接过滤；它们不能替代真实 Chrome 中的原生布局与等宽视觉验收。

## 依据

- [Chrome Tabs API](https://developer.chrome.com/docs/extensions/reference/api/tabs)：`splitWithTabId` / `createSplit` 自 Chrome 155 开始提供；识别分屏使用 `splitViewId`。
- [Chrome 官方介绍](https://developer.chrome.com/blog/split-view-api-extensions)：新建标签默认位于右侧。
- [Chromium 分屏视觉数据](https://github.com/chromium/chromium/blob/main/components/split_tabs/split_tab_visual_data.h)：默认 `split_ratio_ = 0.5`。

## 文件

- `extension/`：直接加载的 Manifest V3 插件。
- `tests/`：行为测试，无第三方依赖。
- `demo/`、`tools/demo-server.js`：仅本机监听的验收页面。
